# MCP 끝판왕 요약집 — 비개발자도 한 번에

> 부트캠프에서 *카드뉴스 ②*는 MCP 서버를 사용하고, *주간보고 ③*는 REST API 직접 호출을 합니다. 그 비교의 뼈대가 되는 *MCP* 한 페이지 정리.

---

## 0. 먼저 — 용어 정확히

| 용어 | 정확한 뜻 | 사람들이 흔히 부르는 말 |
|---|---|---|
| **MCP** (Model Context Protocol) | *프로토콜 자체* (표준·규약) | "MCP" |
| **MCP 서버** | 그 표준을 따라 *실제로 일하는 도구* (외부 서비스 제공자가 만든 것) | "Firecrawl MCP", "Notion MCP" — 짧게 줄여 부름 |
| **MCP 클라이언트** | AI 측에서 MCP 서버와 통신하는 라이브러리 | (대화에선 거의 안 나옴) |
| **MCP 호스트** | MCP 클라이언트를 실행하는 앱 | "Claude Code가 MCP 호스트" |

> **비유** — USB-C는 *표준*, USB-C 케이블은 *실물*. 일상에선 둘 다 "USB-C"로 부르지만 *엄밀히는 다름*. 강의·문서에선 *"MCP 서버"*로 명확히 구분하세요.

## 1. MCP가 뭐예요? (가장 쉬운 비유)

### 옛날 핸드폰 충전기 비극

10년 전엔 폰마다 충전 단자가 달랐어요:
- 갤럭시 5핀 / 8핀
- 아이폰 30핀 → Lightning
- 노키아 다른 거
- LG 또 다른 거

가족이 폰 살 때마다 *케이블 한 박스*가 늘었습니다. 친구 집에서 충전 못 해서 곤란했죠.

### 그러다 USB-C

2017년쯤부터 USB-C 하나로 통일되기 시작. 이제 **케이블 하나로 모든 폰·노트북·아이패드** 충전. 단자 종류 외울 필요 없음.

### AI에도 똑같은 일이 일어남

2024년 11월 이전엔 ChatGPT·Claude·Gemini 각각 *외부 도구 연결 방식*이 다 달랐어요. 같은 기능(예: "웹페이지 본문 가져오기")을 만들려면:
- ChatGPT 용 코드 따로
- Claude 용 코드 따로
- Gemini 용 코드 따로

이걸 *Anthropic이 2024.11에 MCP를 발표*하고 표준화. 1년 만에 **OpenAI(2026.3) · Google Gemini(2026.4) · Microsoft Azure AI Foundry · AWS Bedrock 모두 채택**. 이제 AI 측의 *USB-C 표준*입니다.

## 2. MCP "서버"는 그럼 뭐?

**MCP**가 표준(규약)이라면, **MCP 서버**는 그 표준을 따라 *실제로 일하는 도구*.

| 비유 | 예 |
|---|---|
| USB-C *표준* ↔ USB-C *케이블* | MCP ↔ MCP 서버 |
| HTML 표준 ↔ 네이버·구글 사이트 | MCP ↔ Firecrawl·Notion·Slack MCP 서버 |

**우리 부트캠프에서 만나는 MCP 서버 예시**:

| MCP 서버 이름 | 누가 만들었나 | 무엇을 해요 |
|---|---|---|
| **Firecrawl MCP** | Firecrawl (외부 회사) | 웹페이지 → 깨끗한 마크다운 |
| **claude.ai Notion** | Anthropic + Notion 공식 | Notion 페이지·DB 조작 |
| **claude.ai Gmail** | Anthropic + Google 공식 | Gmail 송수신·검색 |
| **자체 사내 MCP** | 우리 회사가 만들 수 있음 | 사내 ERP·재고·인사 시스템 |

## 3. MCP 서버가 동작하는 원리 — 식당 비유로

레스토랑에 가서 *주문 → 음식이 옴* 흐름을 떠올려보세요.

```
┌────────────┐        ┌────────────┐        ┌─────────────┐
│   손님     │        │   종업원    │        │    주방     │
│  (=AI)     │ <───>  │ (=Transport)│ <───>  │ (=MCP 서버) │
│            │        │             │        │             │
│ "오늘의    │        │ 주문 전달   │        │ 메뉴판 보고 │
│  점심?"    │        │             │        │ 음식 만듦   │
└────────────┘        └────────────┘        └─────────────┘
   AI 호스트            MCP 클라이언트         실제 도구·서비스
  (Claude Code)        (라이브러리)         (Firecrawl 등)
```

### 3가지 *부품* (Resources / Tools / Prompts)

MCP 서버는 AI에게 3가지를 보여줍니다:

| 부품 | 의미 | 식당 비유 |
|---|---|---|
| **Tools** | AI가 *실행할 수 있는 함수* | 메뉴판에 적힌 *주문 가능한 요리* |
| **Resources** | AI가 *읽을 수 있는 데이터* | 식당에 비치된 *오늘의 신문* |
| **Prompts** | 재사용 가능한 *명령 템플릿* | 단골이 자주 시키는 *"늘 먹던 거"* |

대부분의 일은 **Tools** 로 해결됩니다.

### Tools 호출 예 (Firecrawl)

```
AI: "이 URL의 본문을 마크다운으로 가져와줘"
   ↓ (Claude Code가 MCP 클라이언트로 변환)
MCP 클라이언트 → Firecrawl MCP 서버에 JSON-RPC 메시지 송신
   ↓
Firecrawl MCP 서버: 자체 로직으로 페이지 크롤링·정제
   ↓
응답 → Claude Code → AI에게 마크다운 반환
   ↓
AI가 사용자에게 "여기 본문입니다" 전달
```

전 과정이 **수 초** 안에 끝납니다. 사용자는 *그냥 자연어 한 마디*만 했을 뿐.

## 4. 언제 MCP 서버를 써요? 4가지 시나리오

### 시나리오 ① 외부 데이터 가져오기
- 웹 페이지 크롤링 → **Firecrawl MCP**
- 회사 위키 검색 → **Notion MCP**
- 코드 저장소 조회 → **GitHub MCP**

### 시나리오 ② 외부 액션 실행
- 슬랙 메시지 발송 → **Slack MCP**
- 메일 초안 생성 → **Gmail MCP**
- 일정 등록 → **Google Calendar MCP**

### 시나리오 ③ 사내 시스템 연결
- 사내 ERP·인사·재고 → **자체 MCP 서버 구축** (Day 2에서 다룸)
- DB 직접 조회 (read-only) → **Postgres MCP**

### 시나리오 ④ 여러 AI에서 같은 도구 공유
- Claude Code에서 만든 도구를 *Cursor*, *Continue.dev*에서도 그대로 사용
- 회사가 *한 번 만든 사내 MCP*를 모든 AI 도구에서 재사용

## 5. 왜 좋아요? 장점 3가지

### 장점 ① 코드 50줄 → 1줄
*카드뉴스 ②* 에서 봤듯이, Firecrawl을 *MCP 없이* 직접 쓰려면 REST 문서 읽고 코드 짜기 한 시간. MCP 서버 있으면 **자연어 한 줄**로 끝.

### 장점 ② 한 번 만들면 모든 AI에서
회사가 *사내 MCP 서버*를 한 번 만들어두면, Claude·ChatGPT·Gemini 어디서든 *같은 도구* 사용. *AI 갈아탈 때마다 코드 다시 짤 필요 없음*.

### 장점 ③ 권한 관리 명확
MCP 서버 등록 시 `allow / deny / ask` 패턴 — *PM은 조회만, 개발자는 전체, 외부 인턴은 차단* 등 역할별 권한 부여 가능.

## 6. 솔직한 단점 3가지 (★ 강의에서 잘 안 다루는 진짜 얘기)

### 단점 ① 응답 지연
- REST API 직접 호출 → 100ms
- 같은 일을 MCP 서버 거쳐서 → **1~3초**

Claude가 *프롬프트 해석 → MCP 호출 → 응답 해석* 단계를 다 거치니까. **대량 호출** (1만 건+)에는 부적합.

### 단점 ② 디버깅 한 단계 ↑
실패하면 *어디서 막혔는지* 찾기:
- Claude 응답이 이상한 건지?
- MCP 클라이언트가 메시지를 잘못 보냈는지?
- MCP 서버가 죽었는지?
- 진짜 외부 API가 문제인지?

REST 직접 호출은 *코드 한 곳*만 보면 됩니다. MCP는 *여러 단계* 로그를 다 봐야 함.

### 단점 ③ "도구 polluting" (덜 다뤄지는 함정)
MCP 서버를 *너무 많이* 등록하면 — 매 호출마다 모든 도구 설명이 *Claude의 컨텍스트 윈도우*에 자동 포함됩니다. 5개 등록 시 토큰 ~3,000개 그냥 소모. *10개 넘으면 정확도 ↓ + 비용 ↑*.

→ **꼭 필요한 MCP 서버만**. *"있으니까 다 등록"* 금지.

## 7. 부트캠프 케이스 — 두 가지 비교

| | Project ② 카드뉴스 | Project ③ 주간보고 |
|---|---|---|
| 외부 서비스 | Firecrawl | Notion |
| 접근 방식 | **MCP 서버** 사용 | **REST API 직접** 호출 |
| 우리 코드 | 1줄 (`claude -p` subprocess) | 50줄+ (`requests.get` + 토큰 + 파싱) |
| 응답 속도 | 1~3초 | 0.1초 |
| 토큰 관리 | claude.ai가 처리 | `.env` 파일에 직접 |
| 학습 가치 | *AI에 외부 기관 이식* 사고방식 | *인터넷의 기본기*, *완전한 제어* |

→ **둘 다 알아야 옳게 쓴다.** 강사가 이걸 의도적으로 다르게 구성한 이유.
