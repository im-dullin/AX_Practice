1. The USB-C analogy03 / 08

MCP = AI의 USB-C.

10년 전 핸드폰 충전기처럼, AI도 *외부 도구 연결 방식*이 회사마다 달랐어요.
1
Analogy
옛날 (Before)
5핀 · 8핀 · Lightning · Mini USB
갤럭시·아이폰·노키아·LG 다 충전 단자가 달랐다. 친구 집 가서 충전 못 함. 가족 폰 살 때마다 케이블 한 박스 늘어남.
2017~ USB-C
단자 하나로 통일
케이블 하나로 모든 폰·노트북·아이패드 충전. 단자 종류 외울 필요 사라짐. 표준의 위력.
2024.11~ MCP
AI의 USB-C
Anthropic이 표준 발표 → 2026년 OpenAI · Google · Microsoft · AWS 모두 채택. 한 번 만든 도구를 모든 AI에서 재사용.
실무 효과 ①
코드 50줄 → 1줄
Firecrawl을 직접 호출하려면 REST 문서 + 토큰 + 파싱. MCP 서버 있으면 자연어 한 줄.
실무 효과 ②
AI 갈아탈 때 코드 재사용
회사가 한 번 만든 사내 MCP 서버 → Claude · ChatGPT · Cursor 어디서나 같은 도구 사용.
실무 효과 ③
권한 분리 명확
allow / deny / ask 패턴 — PM은 조회만, 개발자는 전체, 외부는 차단. 역할별 다른 노출.

4. Pros · Honest cons06 / 08

장점 3 · 솔직한 단점 3.

강의에서 잘 안 다루는 *현실의 트레이드오프* — 알아야 *옳게* 쓴다.
3+3
Trade-off
Pros — 좋은 점

왜 좋아요?

① 코드 50줄 → 1줄
Firecrawl 직접 호출 vs MCP 서버 호출. 일주일 → 한 시간.
② 한 번 만들면 모든 AI에서
회사가 만든 사내 MCP 서버 → Claude · ChatGPT · Cursor 어디서나 재사용.
③ 권한 분리 명확
allow / deny / ask 패턴으로 역할별 노출 다르게. 보안 + 안전벨트.
Cons — 솔직한 한계

단점도 있어요.

① 응답 지연 (Latency)
REST 직접 100ms → MCP 서버 1~3초. 대량 호출에 부적합.
② 디버깅 한 단계 ↑
AI · MCP 클라이언트 · MCP 서버 · 외부 API 4단계 중 어디가 문제인지 다 확인.
③ 도구 polluting
MCP 서버 너무 많이 등록하면 매 호출에 토큰 ~3,000 자동 소모. 10개 넘으면 정확도 ↓ 비용 ↑.
