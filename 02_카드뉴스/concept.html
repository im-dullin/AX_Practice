★ Core concept · MCP server04 / 06

MCP 서버가 뭐예요?

이 프로젝트의 *진짜 학습 포인트*. AI에게 *외부 기관*을 이식하는 표준.
★
Key concept

비유 — AI의 USB-C

옛날엔 폰마다 충전 단자가 달랐어요 (5핀·8핀·Lightning). USB-C로 통일된 후 *케이블 하나*면 다 됨. AI도 똑같이 *MCP*로 통일됨 (2024.11 Anthropic 발표 → 2026년 OpenAI·Google·MS·AWS 모두 채택).

MCP = 표준 (규약)
MCP 서버 = 그 표준을 따라 실제로 일하는 도구
↳ Firecrawl MCP 서버 = 웹 본문 추출 도구

없으면? vs 있으면?

Firecrawl을 *MCP 없이 직접* 쓰려면 — REST 문서 읽고, requests.get 코드 짜고, API 키 환경변수 관리, 응답 파싱, 에러 핸들링... 한 시간.

MCP 서버 있으면:
claude -p "이 URL을 firecrawl_scrape로"
--allowedTools mcp__firecrawl__firecrawl_scrape
한 줄 끝. 코드 50줄 → 1줄.

5 concepts you learn05 / 06

핵심 개념 5가지.

만들면서 손으로 익히는 *AI 시대 자동화 기본기*.
05
Core
01
★ MCP 서버 등록과 호출
claude mcp add 한 줄로 새 도구 장착. *AI에 외부 기관 이식*. 이 프로젝트 핵심.
02
헤드리스 브라우저
Playwright가 *눈에 안 보이는 Chrome*을 띄워 HTML → PNG. 디자인을 코드로.
03
웹 UI vs CLI 둘 다
비개발자는 Flask 웹 폼, 개발자는 CLI. *같은 코드 두 진입점*.
04
비동기 처리 (async/await)
PNG 5장을 *동시에* 찍어 5초 안에. 기다림을 줄이는 패턴.
05
UX의 마지막 한 발
5장 따로 vs ZIP 한 묶음. *작은 디테일*이 *실제 사용*을 가른다.

MCP의 *솔직한* 단점도.

강의에서 잘 안 다루는 *현실의 트레이드오프* — 알아야 *옳게* 쓴다.
3
단점
단점 ①
지연 (Latency)
REST 직접 100ms → MCP 1~3초. Claude가 중간에 끼니까. *대량 호출*엔 부적합.
단점 ②
디버깅 한 단계 ↑
실패하면 어디 막혔는지 *Claude 응답 + MCP 로그* 둘 다 확인.
단점 ③
초기 등록 비용
가입 + 키 발급 + claude mcp add 한 번. 일회성 사용엔 오버.
실무 응용 ①
자기 회사 블로그 URL
사내 보도자료 / 블로그 단건 → 5장 카드 자동. 마케팅팀 즉시 사용.
실무 응용 ②
Instagram Graph API
PNG 5장 → 인스타 자동 임시저장. 사람은 *검수만*.
