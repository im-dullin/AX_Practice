# 카드뉴스 자동 제작 — 프로젝트 개념 한눈에 보기

> **한 줄 정의**: 기사 URL 한 줄을 넣으면 본문의 *핫이슈*를 분석해 **인스타용 카드 5장(1080×1080)**을 자동으로 만들어주는 *AI 디자이너*.

> ★ **이 프로젝트의 학습 포인트**: 세 프로젝트 중 처음으로 **MCP 서버**를 도입합니다. *AI가 인터넷 페이지를 직접 가져오는* 방법을 손으로 익혀요.

---

## 1. 어떤 문제를 풀어요?

마케팅·홍보 담당자라면 이런 일이 매주:
- 흥미로운 기사 봤는데 *우리 톤*으로 다시 정리하려면 한 시간
- 디자이너에게 *부탁 → 검수 → 수정* 사이클이 3일
- 인스타에 *지속적으로* 콘텐츠를 올려야 하는데 *지속이 안 됨*

이 프로젝트는 **URL 한 줄 → 5분 만에 카드 5장 + ZIP 다운로드**까지 끝냅니다. 디자이너 없이.

---

## 2. 어떻게 동작해요?

```
   [URL 한 줄 입력]
        │  🌐 http://news.example.com/article-123
        ▼
   🕸 Firecrawl MCP 서버 → 페이지 본문 추출
        │  ★ 여기서 MCP 서버 등장!
        ▼
   📄 깨끗한 마크다운 본문이 들어옴
        │  (광고·메뉴·푸터 다 제거됨)
        ▼
   🧠 Claude가 핫이슈 3개 + 카드 5장 콘텐츠 설계
        │  cover · body × 3 · outro 구조
        ▼
   🎨 Playwright 헤드리스 브라우저가 1080×1080 PNG 5장 렌더
        │
        ▼
   🗜 ZIP 한 묶음 + 미리보기 페이지 자동 오픈
        │
        ▼
   📥 사용자: ZIP 다운로드 → 인스타 업로드
```

**전체 6단계 — 사람은 URL 입력과 ZIP 다운로드만.**

## 3. 부품 비유

| 부품 | 비유 | 무엇을 해요 |
|---|---|---|
| **Flask** | 식당 카운터 | 웹 입력 폼 + 결과 페이지 제공 |
| **Firecrawl MCP 서버** | 신문 스크랩 대행사 | URL만 주면 *깨끗한 본문만* 가져다줌 (광고·메뉴 제거) |
| **Claude Code CLI** | 카피라이터 | 본문 → 카드 5장 콘텐츠 설계 |
| **Playwright + Chromium** | 사진 스튜디오 | HTML 페이지를 *진짜 사진처럼* PNG로 찍음 |
| **Pretendard 폰트** | 디자인 시스템 | 한국어가 깔끔하게 보이는 무료 웹폰트 |
| **Python zipfile** | 상자 포장 | PNG 5장을 한 ZIP에 묶음 |

## 4. ★ 핵심 개념 — MCP 서버란?

이 프로젝트의 *진짜 학습 포인트*. 여기서 처음 만나니까 정확히 짚습니다.

### MCP는 *AI의 USB-C*

옛날에는 핸드폰마다 충전 단자가 다 달랐어요 (5핀·8핀·Lightning…). 어느 날 **USB-C 하나로 통일**되면서, 케이블 하나로 모든 폰을 충전할 수 있게 됐습니다.

AI도 마찬가지였어요. ChatGPT·Claude·Gemini가 각각 *외부 도구 연결 방식*이 달랐는데, 2024년 11월 Anthropic이 **MCP (Model Context Protocol)** 를 발표했고, 1년 만에 *OpenAI·Google·Microsoft·AWS 모두 채택*. 이제 AI 측의 *USB-C 표준*입니다.

### MCP "서버"는?

**MCP가 표준(규약)** 이라면, **MCP 서버는 실제로 일하는 도구**입니다.

- USB-C *표준* ↔ USB-C *케이블*
- **MCP** *표준* ↔ **MCP 서버** *실물*

Firecrawl이 만든 "웹페이지 본문 추출 서비스"를 우리는 *Firecrawl MCP 서버*를 통해 사용합니다. AI(Claude)가 "이 URL 가져와줘" 하면 Firecrawl MCP 서버가 받아서 일하고, 깨끗한 마크다운으로 돌려줍니다.

### 왜 좋아요? 안 쓰면 어떻게 돼요?

**MCP 서버 없이** 한다면:
1. Firecrawl REST API 문서 읽고
2. Python으로 `requests.get(...)` 호출 코드 작성
3. API 키 환경변수 관리
4. 응답 파싱 코드 작성
5. 에러 핸들링 ...

**MCP 서버 있으면**:
```bash
claude -p "이 URL을 firecrawl_scrape로 가져와줘" \
  --allowedTools mcp__firecrawl__firecrawl_scrape
```
한 줄로 끝. Claude가 알아서 처리.

### 그럼 단점은?

솔직히 짚어드립니다:
- **지연**: REST 직접 100ms → MCP 1~3초 (Claude가 중간에 끼니까)
- **디버깅 어려움**: 실패하면 *어디서* 막혔는지 한 단계 더 찾아야 함
- **MCP 서버 등록 필요**: 처음 한 번 가입·키 발급·`claude mcp add` 명령

→ *간단한 일회성*은 REST 직접, *반복 사용·여러 AI 공유*는 MCP. 둘 다 알아야 합니다.

## 5. 핵심 개념 5가지 — 만들면서 배우는 것

### ① MCP 서버 등록과 사용 ★
`claude mcp add ...` 한 줄로 새 도구 장착. 이후 모든 Claude 세션에서 사용 가능. *내 AI에게 새 기관을 이식하는 것* 같은 일.

### ② 헤드리스 브라우저 — *코드로 스크린샷*
Playwright가 *눈에 보이지 않는 Chrome*을 띄워 HTML 페이지를 PNG로 찍어줍니다. *디자인을 코드로* 만드는 시대.

> 비유 — 카탈로그 인쇄. 디자이너가 PSD 하나 만들면 그걸로 1000장 찍어내는 거랑 같음.

### ③ 웹 UI vs CLI
이 프로젝트는 둘 다 지원. *비개발자*는 웹 UI (Flask)로 폼 입력, *개발자*는 CLI(`python3 run.py <URL>`). **같은 코드, 두 가지 진입점.**

### ④ 비동기 처리 — `async/await`
Playwright가 페이지 5장을 스크린샷 찍을 때 *동시에 진행*. 그래서 5장이 5초 안에. *기다림을 줄이는* 패턴.

> 비유 — 식당에서 주문 5개를 한 줄로 처리하면 50분, 동시에 처리하면 10분.

### ⑤ ZIP 한 묶음 — 사용자 경험의 마지막 한 발
PNG 5장이 따로따로 있으면 사용자가 *5번 우클릭*. 한 ZIP으로 묶으면 *클릭 한 번*. 작은 차이가 *실제로 쓰이는지*를 가른다.

## 6. 응용 — *내 회사*에 어떻게 가져가요?

| 입력 변경 | 결과 | 누구에게 좋아요 |
|---|---|---|
| 기사 URL → **자기 회사 블로그** | 신상 콘텐츠 5장 자동 | 마케팅 |
| 기사 URL → **사내 위키 페이지** | 사내 발표 슬라이드 자동 | HR / 교육 |
| 기사 URL → **고객사 보도자료** | 영업 자료 자동 | 영업 |
| 출력 PNG → **Instagram Graph API** | 검수 후 자동 발행 (L4) | 마케팅 |
| 출력 PNG → **Notion DB 자동 등재** | 콘텐츠 캘린더 자동 채움 | 콘텐츠팀 |

**Week 1 미션** — 자기 회사 블로그 URL 하나 넣어 카드 5장 만들기.

## 7. 이 프로젝트로 *배워서 가는* 것

- ✅ **MCP 서버를 등록하고 호출**하는 손맛
- ✅ *외부 도구를 AI에 장착*하는 사고방식 — 일을 *직접 코딩* 말고 *AI에게 위임*
- ✅ *헤드리스 브라우저*로 코드 → 이미지 변환
- ✅ 비개발자도 쓸 수 있는 *웹 UI* 설계
- ✅ *사용자 경험의 마지막 한 발* — ZIP 한 묶음 같은 작은 디테일
