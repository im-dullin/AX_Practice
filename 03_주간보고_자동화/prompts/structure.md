## 출력 스키마 (JSON 코드블록 하나로만 응답)

```json
{{
  "headline": "한 줄로 그 주를 요약 (50자 이내, 가능하면 핵심 메트릭이나 결정 포함)",
  "metrics": [
    {{"label": "지표명 (예: 스프린트 달성률)", "value": "현재값 (예: 92%)", "delta": "변화 (예: +32%p, 또는 빈 문자열)"}},
    {{"label": "...", "value": "...", "delta": "..."}},

  ],
  "before": ["지난 주에서 이어진 작업이나 열린 이슈 (한 주 시작 시 상태)"],
  "progress": ["이번 주 완료·배포·합의된 것 (활동 X, 결과 O)"],
  "decisions": ["이번 주 내린 결정 + 근거 (왜 그렇게 결정했는지)"],

```

## 작성 원칙 (반드시 지킬 것)

### 1. 원문 충실성 (가장 중요)
- **원문에 없는 사실을 절대 만들지 마세요**
- 모호하면 끝에 `(확인 필요)` 라벨을 답니다
- 핵심 수치·날짜·담당자·고유명사는 누락 금지

### 2. 활동 vs 결과 구분
- ❌ "회의 5번 진행" (활동)
- ✅ "결제 모듈 v2.3 운영 배포 완료, 성공률 99.7% → 99.9% 개선" (결과)
- `progress`는 **결과만**. 활동은 가능하면 메트릭이나 결정으로 묶기

### 3. 섹션별 가이드
- **metrics**: 메모에 명시된 숫자·%·전후 변화를 우선. 3개 권장(최소 1개~최대 5개). 명시된 메트릭이 없으면 빈 배열 `[]`
- **before**: 2~3개. 지난 주에 시작·열렸지만 끝나지 않은 것
- **progress**: 2~4개. 결과 중심. 메트릭이 있으면 함께
- **decisions**: 1~3개. **결정 내용 + "왜"의 근거**가 한 문장에 들어가야 함. 예: "PG사를 토스로 결정 (수수료 -0.3%p, 정산 T+2)"
- **lessons**: 0~2개. 배운 것이 메모에 없거나 모호하면 빈 배열. 학습 없는 주가 정상
- **next**: 2~4개. 담당자·날짜 명시. 단순 todo가 아니라 *deadline 있는 액션*
- **asks**: 0~3개. **타인이 행동할 수 있어야** 함. 예: "토스 계약서 법무 검토 요청 (5/22까지)", "Q3 OKR 경영진 승인 필요 (5/22 보고)". 본인이 알아서 할 일은 next로
- **risks**: 1~3개. 장애·블로커·외부 의존성

### 4. 톤
- 압축적·실무체. 어려운 단어 X
- 각 불릿은 30~80자 권장 (너무 짧으면 빈약, 너무 길면 읽기 부담)

### 5. 빈 섹션 처리
- 해당 주에 그 섹션에 들어갈 게 없으면 **빈 배열 `[]`** 반환
- 억지로 채우지 말 것 (lessons·asks·decisions는 자주 비어있을 수 있음)
