# 강사용 세팅 매뉴얼 — 시그니처 시연 ③ 주간보고 자동화

> 사용자(강사)가 수업 진행 시 참고하는 운영 매뉴얼. 사양 문서가 아닌 **시간순 액션 가이드**.

---

## 0. 시스템 한 줄 요약

Notion 한 페이지에 일별 토글로 메모만 적으면 → 웹앱이 일 잘하는 사람의 **7섹션 주간보고**(헤드라인 + 메트릭 + BEFORE/PROGRESS/DECISIONS/LESSONS/NEXT/ASKS/RISKS)로 자동 정리해 HTML로 보여준다.

---

## 1. 사전 준비

### 수업 1주 전 (수강생 배포용)

수강생에게 미리 보내야 할 것:

- [ ] **사전 setup 안내 PDF/슬랙 메시지**:
  - Python 3.10+ 설치 확인 (`python3 --version` 또는 `python --version`)
  - Claude Code 설치 확인 (`claude --version`)
  - Notion 계정 보유
  - Notion 워크스페이스에 **"주간보고"라는 페이지 1개** 만들어 오기 (오늘 날짜 토글 1개 + 그날 업무 3~4개 적어와야 시연 가능)
  - Windows 사용자는 PowerShell 7+ 권장

- [ ] **현장 대비 백업 자료** (강사 노트북에 미리 둘 것):
  - 본인 Notion에 한 주치 합성 메모 채워둔 시연용 페이지 URL
  - `.env`에 정상 토큰 채워진 작업 디렉토리 (의존성 설치까지 완료)
  - 사전 생성된 HTML 보고서 1~2개 — 인터넷·Notion API 장애 시 화면 공유로 대체

### 수업 당일 30분 전

- [ ] 노트북 한 대 데모 전용으로 분리. 화면 미러링·공유 준비
- [ ] `cd 08_시그니처시연/03_주간보고_자동화 && source .venv/bin/activate && python app.py` 1회 dry run → 브라우저 자동 오픈 + 폼 정상 표시 확인
- [ ] 시연용 Notion 페이지에 **이번 주 날짜로** 토글 메모 3~4일치 채워두기 (과거 주만 있으면 "이번 주 메모 없음" 에러 → 백업으로 기준일 옵션 사용)
- [ ] 페이지 우상단 ··· → 연결에 Integration이 추가돼 있는지 확인 (`200 OK`)
- [ ] WiFi 안정성 확인 (Notion API + claude CLI 모두 인터넷 필요)

## 2. 시연 흐름 (분 단위 타임라인)

**총 60~75분 블록 기준** (16h 중 Day 1 오후 또는 Day 2 오전 슬롯).

### [0:00 — 0:05] 인트로 · 가치 제시 (5분)

**열기 한 줄**:
> "월요일 아침마다 1시간 30분씩 주간보고 쓰던 거, 일요일 밤에 5초로 끝낼 수 있다면?"

**핵심 메시지**:
- 주간보고는 거의 모든 직장인의 공통 luxury tax
- 작성 자체가 가치를 만들지는 않음 (정보는 이미 본인 머리·메모에 있음)
- LLM이 잘하는 일 = "흩어진 메모 → 구조화된 문서" 정확히 일치
- 더 나아가: 일 잘하는 사람의 보고서 양식까지 자동 학습

**시각 자료**: [[01_커리큘럼_전략]] 16업무 매트릭스 보드에서 **#2 리포팅 칸 형광펜** 표시 ("이 칸을 지금부터 한 시간 안에 진짜 동작하는 시스템으로 만듭니다")

### [0:05 — 0:20] 사용자 입장 라이브 시연 (15분)

**연출**: 강사가 사용자 입장으로 처음부터 끝까지 화면 공유.

```
1) Notion 페이지 열기 (시연용 URL)
   → 일별 토글 4~5개 보여주기 (오늘 날짜 포함)
   → 토글 펴서 안에 체크박스·표·중첩 paragraph 보여주기
   → "여러분도 평소 이렇게 메모하시잖아요"

2) 다른 탭에서 http://localhost:5000 열기
   → 미니멀 UI 보여주기 ("도구처럼 안 생긴 도구")
   → URL 붙여넣기 → "보고서 생성"

3) 약 15~30초 로딩
   → 그 사이 강사 한마디:
     "지금 뒤에선 Notion API 호출 + 토글 자식 재귀 fetch +
      claude CLI 호출 + JSON 파싱 + HTML 렌더링이 일어나고 있습니다"

4) 결과 화면 — 짚어줄 순서:
   ① 헤드라인 한 줄 ("30초 안에 이 한 줄만 봐도 무슨 주였는지")
   ② 메트릭 카드 3개 (스프린트 92%, 결제 성공률 99.9%, 채용 1명)
   ③ 7섹션 BEFORE / PROGRESS / DECISIONS / LESSONS / NEXT / ASKS / RISKS
      → 각 섹션이 어떻게 다른지 한 줄씩:
        · BEFORE = 지난 주에서 이어진 것 (시간 흐름)
        · PROGRESS = 활동이 아닌 "결과"
        · DECISIONS = 결정 + 근거 (왜)
        · LESSONS = 배운 것 (일 잘하는 사람의 핵심)
        · NEXT = 내 todo (담당자·날짜)
        · ASKS = 타인의 행동을 요청 (상사가 30초 안에 액션)
        · RISKS = 남은 우려
   ④ "(확인 필요)" 라벨 짚어주기 → "AI가 원문에 없는 사실을 만들지 않게 한 가드레일"
```

**핵심 메시지**: "AI가 의견을 내되, 원문을 넘어선 거짓말은 안 한다 + 일 잘하는 사람의 양식을 강제한다" — 가드레일 + 베스트 프랙티스 양식 = 신뢰의 핵심.

### [0:20 — 0:35] 코드 워크스루 (15분)

**보여줄 4가지 파일만** (다 보여주려 들지 말 것):

1. **`prompts/structure.md`** ⭐ — "AI의 의견이 만들어지는 진짜 장소"
   - 7섹션 JSON 스키마
   - 가드레일 한 줄 ("원문에 없는 사실 만들지 마세요 ... '(확인 필요)' 라벨")
   - **활동 vs 결과 구분 규칙** (예시까지 명시)
   - **회사 양식에 맞추려면 이 파일 한 줄 고치면 끝** → 30일 미션의 핵심
2. **`app.py` 의 `structure_with_claude` 함수** — "subprocess로 claude CLI 호출"
   - API 키 없이 동작 = Claude Code 인증 재활용
   - 정규식으로 JSON 추출 (LLM 응답 안전 파싱 패턴)
3. **`app.py` 의 `collect_block_lines`** — "Notion 트리 재귀 평탄화"
   - 토글 → paragraph → 자식 → table_row까지 깊이 우선
   - 들여쓰기로 구조 보존
   - 외부 API 다루는 모든 시스템에서 만나는 lazy load 패턴
4. **`templates/report.html`** — "디자인 = 가드레일의 시각화"
   - 모노크롬 + hairline + 큰따옴표 헤드라인
   - "도구처럼 안 생긴 도구" = 직장인이 거부감 없이 받아들임

**핵심 메시지**: 코드 양은 적지만 (앱 ~300줄), **결정의 밀도가 높다**. 결정 = 가드레일 + 사용자 흐름 + 출력 양식. 양식은 `prompts/structure.md` 한 파일에 응축.

### [0:35 — 1:05] 수강생 따라하기 (30분)

**진행 방식**: 강사가 1단계씩 시연 → 수강생이 따라 → 강사가 "여기까지 된 분 손" 확인 → 다음 단계.

```
[1] 페이지 준비 (3분)
    수강생: 본인 Notion에 "주간보고" 페이지 만들기
    → 오늘 날짜 토글 1개 + 그날 업무 3~4개 적기

[2] Notion Integration 토큰 발급 (5분)
    https://www.notion.so/profile/integrations → 신규 연결
    이름: 본인 알아볼 이름 / 인증: 액세스 토큰 / Capabilities: Read/Update/Insert ON
    → 토큰 복사

[3] 페이지에 Connection 추가 (2분, 가장 자주 놓치는 단계)
    페이지 우상단 ··· → 연결 → 본인 Integration 검색·추가
    → "이거 안 하시면 다음 단계에서 모두 404 뜹니다" 강조

[4] 작업 디렉토리 셋업 (5분)
    GitHub 또는 사전 배포한 zip에서 03_주간보고_자동화 복사
    cp .env.example .env  →  NOTION_TOKEN= 뒤에 토큰 붙여넣기
    python3 -m venv .venv && source .venv/bin/activate
    pip install -r requirements.txt

[5] 토큰 sanity check (2분)
    PROMPT.md의 "검증 1" 스크립트 한 줄
    → "200 OK + Integration 이름" 확인

[6] 첫 실행 (10분)
    python app.py → 브라우저 자동 오픈
    본인 페이지 URL 붙여넣고 생성
    → 본인 데이터로 본인 7섹션 보고서가 만들어지는 경험
    → 강사·TA가 돌아다니며 401/404 막힌 사람 케이스 즉시 해결
    → 결과물 보고 "어느 섹션이 가장 의외였는지" 짧게 공유
```

**핵심 메시지**: 30분 안에 **본인 데이터로 본인 보고서**가 만들어지는 경험 = 재수강 후킹. 한 명이라도 막히면 멈추고 같이 해결.

### [1:05 — 1:15] 마무리 · 30일 미션 안내 (10분)

- 오늘 만든 것은 "원형"이고, 30일 안에 본인 환경에 맞춰 5가지 확장 미션 (아래 §5)
- 1주차 미션: `prompts/structure.md`의 7섹션 이름·정의를 본인 회사 양식에 맞게 수정
- 1순위 추천: `metrics` 정의를 본인 KPI에 맞추기 (예: "MAU", "리드 전환율", "PR 처리 시간")

## 3. 핵심 시연 포인트 (놓치면 안 되는 8가지)

1. **사용자가 메모를 만든 곳(Notion) = 보고서가 돌아갈 곳(Notion)** — 평소 습관을 깨지 않는 자동화가 좋은 자동화
2. **토글 안의 토글·표·체크박스까지 재귀 추출** — 사용자 페이지 구조가 16명 다 달라도 동작
3. **"확인 필요" 라벨이 자동으로 붙음** — AI는 모르는 걸 모른다고 말할 수 있어야 함
4. **메트릭 카드 3개 헤더** — "활동"이 아닌 "결과"를 시각적으로 분리
5. **DECISIONS 섹션** — "무엇"만이 아니라 "왜". 후임도 같은 판단 내릴 수 있게
6. **LESSONS 섹션** — 일 잘하는 사람과 보통 사람의 가장 큰 차이
7. **ASKS 섹션** — 상사가 30초 안에 *행동할 수 있는 것*이 명확
8. **API 키 없이 동작** — `claude -p` 서브프로세스 = Claude Code 인증 재활용

## 4. 실시간 트러블슈팅 (수업 중 자주 발생)

| 증상 | 즉시 해결 |
|---|---|
| 수강생 절반이 `Notion API 403/404` | "페이지 ··· → 연결 추가" 다시 보여주기. 워크스페이스 권한과 별개임 강조 |
| `이번 주 메모가 없어요` + 가장 최근 데이터 안내가 뜸 | 시연 페이지에 **오늘 날짜** 토글 있는지 확인. 없으면 기준일을 안내된 날짜로 입력 |
| `claude CLI를 찾을 수 없습니다` | Claude Code 설치 확인. PATH 문제면 셸 재시작 |
| Windows에서 `[WinError 2]` | `subprocess.run`에 `shell=True` 누락. 사전 배포 zip이 macOS 버전인지 확인 |
| 한글 깨짐 (Windows) | PowerShell 7+ 사용 + `$env:PYTHONIOENCODING="utf-8"` |
| WiFi 끊김 / Notion API 다운 | **백업 시나리오 전환**: 사전 생성된 HTML 보고서 화면 공유로 결과만 보여주고 토큰 발급 단계로 넘어가기 |
| `pip install`이 느림 (16명 동시) | "5분 드릴게요. 끝난 분은 손 들어주세요" — 자연스럽게 Q&A 시간 |
| 결과 보고서에 LESSONS·ASKS가 비어 보임 | 메모 자체에 학습·요청 사항이 없으면 정상 (가드레일이 빈 배열 반환). "그래서 빈 섹션은 표시 자체 안 합니다" 설명 |
| 메트릭 카드가 1~2개만 나옴 | 메모에 명시된 숫자가 적으면 LLM이 안전하게 줄임. "다음 주엔 메모에 숫자를 더 적어보세요" 가이드 |
| Integration 토큰 노출 위험 | "토큰 = 비밀번호. `.env`에만 두고 `.gitignore` 확인. 슬랙·git에 올리지 마세요" 짧게 강조 |

## 5. 확장 시연 시나리오 (시간 남으면)

**난이도순으로** 5가지. 시간 5~10분씩.

### A. 출력 양식 교체 (5분, 비개발자도 가능) ⭐ 가장 추천
`prompts/structure.md` 한 파일만 수정.
- 7섹션 이름을 본인 회사 양식으로 (KPI/이슈/일정/요청사항 등)
- 헤드라인 50자 → "두 줄까지 허용"
- "확인 필요" 라벨을 더 엄격하게/느슨하게
- 메트릭 정의를 본인 KPI에 맞추기

### B. Slack 발송 추가 (10분)
`app.py`의 `generate()` 끝에 webhook POST 한 줄 추가.
```python
requests.post(SLACK_WEBHOOK, json={"text": f"📊 W{week_num} 주간보고: {report['headline']}"})
```

### C. Cron 자동 실행 (5분)
일요일 21시 자동 실행 (macOS):
```bash
crontab -e
0 21 * * 0 cd /path/to/proj && .venv/bin/python app_headless.py <URL>
```

### D. Notion DB 인덱스 (10분)
한 페이지에 누적이 아니라 데이터베이스로 승격 — 검색·필터·뷰가 필요해진 시점 (보통 3~6개월 후).

### E. 다른 페이지로 재사용 (5분)
같은 시스템으로:
- 팀 회고 페이지 → 월간 회고 보고서
- 클라이언트 미팅 노트 → 분기별 고객 인사이트 리포트
- 학습 일지 → 주간 학습 회고

→ **"파이프라인의 가치는 입력을 갈아끼울 수 있다는 것"**

## 8. 7섹션의 출처 (수강생 질문 대비)

> "왜 BEFORE/PROGRESS/NEXT/RISK만이 아니라 DECISIONS/LESSONS/ASKS도 있나요?"

답변 한 줄:
> "일 잘하는 사람들의 주간보고는 활동 나열이 아니라 **결과·결정·배움·요청**을 분리해서 보여줍니다. 우리는 그 베스트 프랙티스를 양식으로 강제한 거예요."

레퍼런스 5가지 (출처 명시 가능):
- **Stripe (Patrick Collison memo)**: TL;DR → 메트릭 → 결정+근거 → Asks
- **Andy Grove "High Output Management"**: 했는가 / 배웠는가 / 안 풀리는가 / 다음 / 도움 필요
- **YC weekly update**: 헤드라인 + 메트릭 변화 + 원인 분석 + 다음 목표
- **Linear / Shopify digest**: Shipped / In flight / Up next / Blockers
- **OKR weekly check-in**: KR % + Green/Yellow/Red + 행동 트리거

공통: **메트릭 우선 · 결정의 근거 · 배움 · 도움 요청 · 30초 헤드라인**
